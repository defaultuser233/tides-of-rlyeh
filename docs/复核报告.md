### R1　匕首一次挥砍结算三次伤害　`[已亲自复核]`

**严重度：严重回归（重写引入）**

**定位**：`src/main.rs:2697-2750`（`fire_player_shot` 的近战路径）

**现状代码**

```rust
// A knife is a swing, not a shot: short reach, no falloff, no tracers.
let (rays, range) = if s.melee {
    (3, 2.6)
} else {
    (s.pellets, weapon::MAX_RANGE)
};
// ...
// A knife gets the plain round: one target and no cover budget, so a swing
// stops in the first thing it meets — which is also why its swing is three
// rays into one arc.
let round = game.arsenal.active_weapon().penetration();
for _ in 0..rays {
    let dir = game.rng.cone(game.player.look_dir(), spread);
    let lane = combat::hitscan_through(&game.level, &game.enemies, eye, dir, range);
    let swept = combat::sweep(&lane, round);

    for (body, share) in &swept.hits {
        game.shots_hit += 1;
        let dmg = game.arsenal.active_weapon().damage_at(body.dist) * /* … */ * share;
        let pen = game.arsenal.active_weapon().armor_pen();
        let died = game.enemies[body.index].take_damage(dmg, pen);   // ← 每条 ray 各结算一次
        // 血、伤害数字、命中标记、音效……
```

**失败模式**

旧代码在近战分支有一条 `if s.melee { break; }`，重写时被删除，于是三条射线**各自跑完整的伤害循环**。

匕首的 `base_spread` / `bloom_per_shot` / `max_bloom` 全部为 `0.0`，`spread()` 只再叠加移动项。**站定挥砍时 `rng.cone(dir, 0.0)` 返回的就是 `dir` 本身，三条射线完全相同**；即使冲刺，散布在 2.6 m 触及距离上也只有几厘米，仍落在任何敌人的 AABB 内。

后果：

- **一刀 = 3 倍伤害**（注释里那个"arc"并不存在）；
- 3 份血粒子、3 个浮动伤害数字、3 声命中音、命中标记叠加；
- `shots_hit` 每次多记 2 次，命中率可超过 100%（见 R9）。

**修法**

在一次挥砍内按敌人索引去重，命中只结算一次。缓冲区建议复用（挂在 `Game` 上，与 `damage_labels` 同法），避免每次挥砍分配：

```rust
// 进函数前，或复用一个挂在 Game 上的 scratch buffer
game.swing_hits.clear();
game.swing_hits.resize(game.enemies.len(), false);

let mut hit_anything = false;
for _ in 0..rays {
    let dir = game.rng.cone(game.player.look_dir(), spread);
    let lane = combat::hitscan_through(&game.level, &game.enemies, eye, dir, range);
    let swept = combat::sweep(&lane, round);

    for (body, share) in &swept.hits {
        if std::mem::replace(&mut game.swing_hits[body.index], true) {
            continue;               // 这一刀已经打中过它了
        }
        hit_anything = true;
        game.shots_hit += 1;
        // …原有的结算逻辑，保持只执行一次
    }
}
```

如果确实想要"挥砍弧线"，正确做法是让三条射线**真的分开**（按 `spread` 偏移每条的 `dir`），但那仍然需要上面的去重——否则同一目标会被相邻射线重复命中。**推荐先做去重，弧线作为后续可选改进。**

**验证**

1. `cargo test` 通过；补一条测试：一次挥砍对单个敌人只造成一次伤害、`shots_hit` 只加 1。
2. 进游戏按 `4` 持刀，对同一敌人挥砍，确认掉血与改前一致（约为此前的 1/3）。
3. 确认命中时只出现一团血、一个伤害数字、一声命中音。

### R2　转盘被状态切换遗留在打开态，鼠标视角彻底冻死　`[代理定位]`

**严重度：BUG（新引入）**

**定位**：`src/main.rs` 的 `Wheel` / `game.wheel`（字段声明在 `main.rs:987`）、转盘关闭逻辑、`resume_play()`（`main.rs:1524`）

**失败模式**

转盘只在 `simulate` 内由 `is_key_released(G/V)` 关闭。操作序列：

1. 按住 `G`（转盘打开，视角增量被强制为 0）；
2. 按 `Tab` 打开覆盖层 —— `simulate` 停止运行；
3. 松开 `G` —— **这次松开边沿没有任何代码在监听**；
4. 关闭覆盖层。

结果：`game.wheel` 仍是 `Some`，`wheel_open` 仍为真，鼠标视角持续为零，指针保持自由状态，滚轮切枪也被阻塞。**唯一的出口是再按一次 `G`——而那一次会把准备中的手雷扔出去。**

**修法**

在 `resume_play()` 与所有覆盖层开启处清空转盘并恢复指针约束：

```rust
fn resume_play(&mut self) {
    self.phase = Phase::Playing;
    self.trigger_armed = false;
    self.mouse_ready = false;
    self.sprint = false;
    // 新增：被遗留在打开态的转盘必须丢弃，否则视角永久为零
    self.wheel = None;
}
```

若转盘状态有多个字段（手雷轮 / 医疗轮），**全部**一起清。更稳的做法是把转盘的存活条件从"按下/松开边沿"改成 `is_key_down(G) && !overlay_open`，这样状态切换时它会自然关闭，而不是依赖某条边沿被某段代码看到。

**验证**

1. 按住 `G` → 按 `Tab` → 松开 `G` → 关闭 `Tab`，确认视角恢复正常、没有扔出手雷。
2. 对 `V` 重复一次。
3. 对 `Esc` 暂停重复一次。

### R3　设置与进度存档是非原子写入，可能丢用户数据　`[代理定位]`

**严重度：BUG（唯一会丢用户数据的问题，优先级高于其观感）**

**定位**：`src/config.rs:301-305`（`save_to`）、`src/config.rs:252-257`（`source_path`）

**现状代码**

```rust
fn save_to(path: &Path, config: &Config) -> std::io::Result<()> {
    // …
    std::fs::File::create(path)?.write_all(render(config).as_bytes())
}
```

**失败模式**

`File::create` **立即截断**，然后才写入。崩溃、`kill -9`、掉电、被杀毒软件中途拦锁，都会留下空文件或半截文件。而 `unlocked` / `best_*` / `build_*` / `paint_*` / 配装**只存在于这个文件里**，下一次启动时没写成功的行会静默回落到默认值。

更糟的是 `source_path`：它**仅在当前路径不存在时**才回退到更名前的旧存档。因此"更名后的第一次保存被打断"会创建一个残缺的新文件，从而**永久放弃磁盘上仍然完好的旧存档**。

**修法**

```rust
fn save_to(path: &Path, config: &Config) -> std::io::Result<()> {
    let tmp = path.with_extension("tmp");
    {
        let mut f = std::fs::File::create(&tmp)?;
        f.write_all(render(config).as_bytes())?;
        f.sync_all()?;                       // 数据先落盘，再改名
    }
    std::fs::rename(&tmp, path)             // Windows 上会替换已存在的目标
}
```

配套两点：

- `source_path` 把**零长度文件**视为"从未写入过"，从而能回退到旧存档；
- `config.rs:275` 的 `save` 目前失败只走到 `eprintln!`，玩家不会知道自己 的设置没有保存。设置页是唯一的用户主动保存入口，建议在那里显示一行提示。

**验证**

1. 写一条测试：保存 → 读回 → 内容一致；保存过程中人为制造失败（把目标路径设为目录）不破坏已有文件。
2. 手工验证：正常启动一次确认配置文件生成；把配置文件截断为 0 字节，确认程序仍能启动且不会覆盖旧存档。

### R5　半截连发跨"松扳机"和"换枪"存活　`[代理定位]`

**定位**：`src/weapon.rs` 的 `try_fire`（`Burst => self.burst_left > 0 || pressed`）、`Arsenal::select`

`burst_left` 只在 `cycle_fire_mode` 与 `start_reload` 里清零，`Arsenal::select` 与 `Weapon::update` 都不碰它。打 1 发就松手，`burst_left = 2` 被冻结；切枪再切回来仍然存在。再次轻按会以连发内部节奏"续掉"残余 2 发，而不是重新开始一次 3 连发——两连点可把一次连发拆成 1+2。

代码自己的契约（`weapon.rs` 中 `A burst completes itself once begun, and does not run on afterwards`）与实现相反：`main.rs:4728` 的外层门槛是 `if alive && (held || pressed)`，松开后 `try_fire` 根本不被调用，所以**连发实际上不会自行完成**。而声称验证这条契约的测试在整个过程中恒传 `held = true`，**结构上测不到这条路径**。

**修法（二选一，必须明确选一个）**

- **A（推荐，改动小）**：把 `burst_left` 视为"本次按住内有效"——在 `Arsenal::select` 里对换下的武器清零（与 `reload_t` / `inspect_t` 同处），并在 `Weapon::update` 里检测"扳机已松开"→ 清零。同时修改那条注释。
- **B（更贴近注释）**：让 `main.rs` 在 `burst_left > 0` 时继续驱动 `try_fire`，真正实现"自行完成"。这需要给 `Weapon` 加一个 `burst_pending()` 查询。

无论选哪个，**都要补一条会松手的测试**——现有测试的 `held` 恒为真，这是它漏掉此 bug 的直接原因。

### R6　穿透的停止点落在"没有被打中"的那个敌人身上　`[代理定位]`

**定位**：`src/combat.rs:167-177`（`sweep` 的 `Step::Body` 分支），消费点在 `src/main.rs:2777-2784`（曳光弹终点）

```rust
Step::Body(body) => {
    if crossed >= round.max_targets {
        return Sweep { hits, stop: Hit { point: body.point, dist: body.dist }, … };
```

预算用尽时，`stop` 取的是**下一个**敌人的入射点。普通弹的 `max_targets = 1`，于是曳光弹**穿过第一个敌人、停在他身后的第二个人身上**——玩家看到的是"打中了第二个却没伤害"。

同一函数末尾的兜底分支（`combat.rs:192-195`）形状相同，只在目标恰好是该弹道最后一个身体时才正确。

顺带一个次序问题：掩体分支（`combat.rs:154`）在目标预算之前判断，所以一颗已经用光三个目标的 AP 弹再撞上墙时仍会报告 `stopped_on_cover = true`，产生一次墙面火花和一条画过第三具尸体的曳光弹。

**修法**：把 `crossed >= max_targets` 的判断提到最前，`stop` 取**最后一个被计入 `hits` 的身体**；掩体只有在"这一发还有预算可花"时才成为停止点。

**验证**：让两个敌人前后成一条线，用普通弹打第一个——曳光弹应停在第一个敌人身上。

### R7　敌人打玩家的射线上还留着贴脸豁免　`[代理定位]`

**定位**：`src/main.rs:4857-4860`

```rust
if let Some(t) = ray_player(&game.player, origin, dir)
    && t > 0.02
```

玩家贴到敌人身上（进入其 0.35 m 半径的 AABB）时 `ray_player` 返回 `0.0`，这一发被丢弃、曳光弹穿身而过、伤害为零。

这与上一轮在玩家侧修掉的是**同一类 bug**（`combat.rs:91-99` 已改为不设下限），敌人侧漏了。

**修法**：去掉 `t > 0.02`，只保留 `&& t < wall`（贴脸情形的 `end` 已经做过钳制，见 `main.rs:4880`）。

### R8　`load=ap` 不按武器筛选　`[代理定位]`

**定位**：`src/weapon.rs:2007-2035`（`AmmoKind::apply`）、`src/weapon.rs:472-484`（`from_text`）

模块文档声称"载弹不筛选：把武器装不进去的弹种给它，它不会有任何变化"，但 `apply` 只守了一条 `AmmoKind::Slug if values[pellets] > 1.0`。`Ap` / `Jhp` 无守卫，而 `Penetration` 是按弹种而非按武器给出的。

**失败模式**：在配置文件里写 `load=ap`，手枪即获得 3 体穿透 + 0.25 m 破墙预算 + 1.1× 破甲。UI 用 `loads()` 限制了下拉选项（`main.rs:3938`），配置路径没有等价检查。

**修法**：在 `screened` 阶段把弹种与该武器的 `WeaponKind::loads()` 对照（需要把 kind 或允许的弹种表传进去），或让 `apply` 遇到"本武器不提供此弹种"时一律退化为 FMJ。

**顺带**（次要不一致）：`from_text` 的槽名匹配忽略大小写，`AmmoKind::from_key` 不忽略。

### R9　命中与命中率统计重复计数　`[代理定位]`

**定位**：`src/main.rs:2702-2720`、结果页 `main.rs:4163-4166`

`shots_hit` 按"每条射线 × 每个身体"累加，于是一颗 AP 弹打穿两个人记 2 次命中；近战则完全不记 `shots_fired`（`main.rs:2704` 只对非近战计数），所以纯刀通的结果页显示"—"，而一次挥砍记 3 次命中。两者叠加可以让命中率远超 100%（例如一次手枪射击配五次挥砍）。

**修法**：命中按"每条射线是否打中任何东西"记 1 次；近战挥砍计入 `shots_fired`。R1 的去重顺带修掉一半。

### R10　`hud.rs` 仍用相对路径加载字体，违反 `assets.rs` 的契约　`[代理定位]`

**定位**：`src/hud.rs:305` 附近

```rust
for path in ["assets/fonts/ui_zh.ttf", "assets/fonts/ui_zh.otf"] {
    // load_ttf_font(path).await …
}
```

`assets.rs` 的模块文档明确写着它是"游戏中唯一知道文件在哪里的地方"，并把相对路径加载列为**本项目已经吃过的一次亏**（`cargo run` 下能工作，发布后可执行文件从任何别处启动就静默失败）。

而这里在 `BUNDLED_FONT` 已经尝试内嵌字体之后，又回退到相对路径。它只会在工程根目录作为工作目录时生效，会静默加载到一个**不同的字体文件**，而且 `ui_zh.otf` 这个文件根本不存在。

**修法**：删除这个循环。内嵌字体要么加载成功，要么回退到内置字体，没有第三种可能。

**顺带**：`src/audio.rs:355` 也有一个 `format!("assets/sounds/{base}.{ext}")` 的探测（作为 mod 覆盖功能）。它是有意为之，但同样使 `assets.rs` 的"唯一契约"不再成立。建议把它收进 `assets::override_path(name)`，或者把两处例外写进两份文档注释。

### R11　`Lane.far` 恒等于 `max`，文档与之矛盾　`[代理定位]`

**定位**：`src/combat.rs:61-84`

文档说 `far` 是"最后遇到的掩体的远侧，没有掩体时为 `max`"，但实现是 `let mut far = max;` 之后只做 `far = far.max(exit)`，而 `level.rs:681` 已把每个 `exit` 钳到 `max_dist` —— 所以 `far` **永远是 `max`**。

后果：穿透弹的曳光弹永远画满 `MAX_RANGE`（约 200 m），而不是"停在墙的远侧"。

**修法**：`let mut far = 0.0;`，没有遇到掩体时再回落到 `max`；或修正文档。

### R12　贴图解码用 `expect`，坏一张就启动即 panic　`[代理定位]`

**定位**：`src/surface.rs:165`

```rust
Image::from_file_with_format(s.png(), Some(ImageFormat::Png))
    .expect("a bundled surface texture is not a decodable PNG")
```

字体（`hud.rs:301-310`）与雾着色器（`fog.rs:97-125`）都选择了优雅降级，只有这里会在启动的第一帧之前直接 panic。

**修法**：记录日志并替换为 1×1 白色贴图，或让 `Textures::load` 返回 `Result` 由调用方容忍缺失。

### R13　生存任务仍然无法提前结束（老问题，只修了一半）　`[代理定位]`

**定位**：`src/campaign.rs:150-165`（数值）、`src/main.rs:5094` / `5117-5130`（胜利条件）

数值已经修好：任务 4 现在约 66 个敌人（原 26），节奏 `(1.05 - 0.04 * difficulty).max(0.45)` ≈ 0.99 s，另有 5 波准备窗口。

**但 `Survive` 分支仍然不读 `cleared`**（`cleared` 已在 `main.rs:5094` 算出来了）。按最短通关算：约 65 秒的释放内容 + 5 × 3 秒准备 ≈ 83 秒，对 120 秒的计时器；而且 `F` 可以跳过准备窗口。**熟练玩家仍会在空场地里等 20–40 秒**，且无法提前撤离。

**修法**：让 `cleared` 停表（计时到点或敌人清空，两者取先），或把敌人在时间轴上摊得更长。

### R15　手雷上限静默删除最旧的一颗　`[代理定位]`（老问题，未修）

if self.live.len() >= MAX_LIVE { self.live.remove(0); }

`MAX_LIVE = 8`。第 9 颗手雷会让飞行中的第一颗**凭空消失**：没有爆炸、没有烟雾、没有音效，网格直接弹出。

### R16　新的射击路径每次都分配并整表排序　`[代理定位]`（性能，低）

**定位**：`src/combat.rs:75-111`、`src/combat.rs:141`

`hitscan_through` 每次调用分配两个 `Vec`（spans + steps），`sweep` 再分配一个。一次霰弹枪射击 = 约 18 次分配，并且对**全部实体**排序 9 次，全都发生在任何命中测试之前。旧的 `hitscan` 是无分配且 O(solids) 的。

## 8. 边界与约束

1. **不要为了修 R1 去重写伤害管线。** 去重是一处局部改动，加一个按索引的 bitset 即可。
2. **不要引入新依赖。** 以上全部问题都不需要新的 crate。
3. **不要动已正确的部分。** 第 2 节列出的实现（尤其是 `surface.rs` 的贴图环绕处理、`level.rs` 的子步细分、`resume_play` 的注释）都已经过验证，重构它们只会带来风险。
4. **保持双语。** 新增任何用户可见文案都必须同时补中英文——`i18n.rs` 的宏会强制这一点。
5. **改动 `combat.rs` 时注意**：`hitscan_through` / `sweep` / `Penetration` 是一套新的、相互耦合的抽象（实体穿透 + 掩体预算 + 距离衰减份额）。R6 / R9 的修复应当保持这套抽象的边界，不要退回旧的单次 `hitscan` 模型。
6. **一个提交一个编号**，提交信息带上编号（例如 `fix(R1): dedupe melee hits so a knife swing lands once`）。
