## 2. 结论

**美术是这个项目最弱的一环，而且问题不是"做得糙"，是一整层素材已经准备好却根本没接线。**

- **UI 是全项目唯一真正被设计过的部分**，完成度可以给 7 分（自洽的调色板、分辨率无关的缩放、有识别度的角标、专业的地图）。
- **场景、角色、武器是 3 分**：全部是代码手搓的纯色盒体，无贴图、无阴影、无 AO、无雾。
- **最新、最贵的那部分素材（6 张 Poly Haven 贴图 + 6 个 Kenney 角色模型）一张都没进画面。**

素材准备工作本身做得非常扎实（降采样、授权溯源、格式约束验证、逐文件清单），这使问题更刺眼：**最后一步没接。**

## 3. 贴图：6 张全部闲置，一张都没加载

### 3.1 证据（三条互相独立）

```
$ grep -rn "load_texture\|Texture2D" src/
（无输出）
```

1. **UV 恒为零。** `src/mesh.rs` 的 `quad()` 里每个顶点硬编码 `uv: Vec2::ZERO`：
   ```rust
   for p in [a, b, c, d] {
       self.verts.push(Vertex { position: p, uv: Vec2::ZERO, color: col, normal: n4 });
   }
   ```
   `add_box` 的六个面全部经由 `quad`，`add_beam` 也复用 `quad`，所以**关卡里每一个面、每一根梁柱的 UV 都是 (0,0)**——采样永远落在第一个纹素。即使挂上贴图，画面上也只会是一片纯色。

2. **网格的贴图槽被写死为 `None`。** `src/mesh.rs` 的 `finish()` 与 `reclaim()` 都返回 `texture: None`。

3. **关卡几何没有材质表达能力。** `src/level.rs` 的关卡盒子类型是：
   ```rust
   pub struct Layout {
       // ...
       pub boxes: Vec<(Vec3, Vec3, Color)>,   // 一个盒子 = 两个角点 + 一个颜色
       // ...
   }
   ```
   `Level::from_layout` 直接 `mb.add_box(*min, *max, *color)`。**没有材质索引，没有 per-face 材质**，所以"地面用混凝土、墙用波纹铁、箱子用集装箱"这件事在当前数据结构下根本无法表达。

### 3.2 截图印证

检视 `target/hudshots/` 下的截图（例如 `1280x720_zh/01_inventory_full.png`、`04_map_full.png`），背景世界就是**几块纯灰、纯棕的平面**，没有任何表面细节。这与"UV 全零、无贴图"的代码结论完全一致。

### 3.3 实际资产的现状

| 资产 | 位置 | 规格 | 状态 |
|---|---|---|---|
| 6 张无缝表面贴图 | `assets/textures/` | 512×512 PNG，共 2.6 MB | **零引用** |
| 6 个 Kenney 方块人 | `assets/models/characters/` | 每个 72 三角面，带独立 limb 分组与贴图 | **零引用** |
| 5 个 Kenney 武器 | `assets/models/weapons/` | 592–1704 三角面，共享 colormap | **零引用** |
| 3 个 Kenney 箱子 | `assets/models/props/` | 各 1000 三角面 | **零引用** |

`assets/MANIFEST.md` 已经把每张贴图的来源、授权、原始 URL 和预期用途（floor / wall / crate）都写清楚了，`src/level.rs` 甚至已经有 `Aabb` 表示——**接线所需的准备工作都做完了，只差代码**。

## 4. 角色：四种人形共用同一个 9 盒模型

### 4.1 模型构成

| 敌人 | 构建函数 | 盒数 | 轮廓可辨识度 |
|---|---|---:|---|
| Grunt / Rusher / Heavy / Sniper | `build_humanoid`（`src/enemy.rs:275`） | **9** | **差**——同一个模型，只是半径 0.36–0.60、身高 1.62–2.30、配色不同 |
| Drone | `build_drone` | 11 | 良 |
| Spawnling | `build_spawnling` | 19 | 良 |
| Tentacle | `build_tentacle` | 42 | 良 |
| Colossus | `write_colossus`（`src/enemy.rs:459`） | 36 | 优 |

人形的 9 个盒子是：两条腿、躯干、肩甲、两条手臂、脖子、两个面罩光点。四种敌人远看是**颜色不同的克隆人**——这在一个以"五种敌人原型互相区分"为卖点的游戏里是明显的落差。

### 4.2 动画：只有巨像会动

`src/enemy.rs:1107` 的注释直说了：**"The colossus is the only archetype whose limbs move"**。

- **巨像**逐帧重建网格，腿部有真正的摆动（`enemy.rs:465-470`：`let cyc = (stride + lag).sin(); let lift = cyc.max(0.0)*h*0.05;`），手臂反相摆动，王冠蠕动，躯干有上下起伏 `bob` 与左右摇摆 `sway`。
- **其余 7 种全部是刚体原型**：整体平移 + 偏航，只有死亡时才有倾倒动画。它们的移动在视觉上是**滑行**，不是行走。

这意味着即使是最基本的"敌人走路时腿会动"这一层，当前也只覆盖了 1/8 的原型。

## 6. 光照：只有烘焙的平面着色

```rust
// src/mesh.rs
const SUN: Vec3 = vec3(-0.42, 0.80, 0.43);

let d   = (n.dot(SUN)).max(0.0);          // 面法线（叉积后归一化）
let sky = (n.y * 0.5 + 0.5) * 0.18;       // 天空反弹
let f   = 0.44 + 0.62 * d + sky;
```

每个四边形算一个面法线，**四个顶点共享同一个颜色 → 完全平直着色，没有任何渐变**。

| 朝向 | 亮度 `f` |
|---|---:|
| 地面（+Y） | **1.116**（超过 1.0，在 `rgba()` 里被钳掉 → 过曝压平） |
| 墙（−X） | 0.79 |
| 墙（+Z） | 0.797 |
| 墙（+X / −Z） | 0.53 |
| 底面（−Y） | 0.44 |

**没有阴影、没有环境光遮蔽、没有雾、没有地面接触暗化。** 结果是整个世界看起来像"同一块灰在不同亮度下"，物体没有重量感，不会"落"在地面上。

天空是 40 段渐变条带（`main.rs:389-410`），顶部约 `sky*0.30/0.32/0.42`，地平线 `sky*0.55+0.12`——**这是全项目除 UI 外唯一一处有色彩设计的地方**。

## 11. 改造建议（按性价比排序）

### A1　接上贴图 —— 最高性价比

**目标**：地面 / 墙面 / 箱子 / 掩体在视觉上彼此可分。

**涉及文件**：`src/level.rs`（数据结构）、`src/maps.rs`（数据）、`src/mesh.rs`（UV）、`src/main.rs`（加载与绘制）

**实现要点**

1. 给关卡盒子加材质：把 `boxes: Vec<(Vec3, Vec3, Color)>` 扩成带材质索引的元组或结构体，例如
   ```rust
   pub enum Surface { ConcreteFloor, MetalPlate, MetalRusty, Corrugated, Crate, Tiles }
   pub struct Block { pub min: Vec3, pub max: Vec3, pub color: Color, pub surface: Surface }
   ```
   `maps.rs` 里 150 处字面量可以先用一个默认值批量套上，再逐关精调。
2. `MeshBuilder` 增加 UV 生成：按面的两个切向轴、以"每米多少贴图"的固定比例计算，**UV 必须随面的物理尺寸变化**，否则 20 m 的墙和 1 m 的箱子会共享同一张贴图拉伸。
3. **一个 `Mesh` 只能有一个 `texture`**（见第 14 节的 API 事实）。所以关卡几何要**按材质拆成多个 `Mesh`**，每个材质一次 `draw_mesh`——不是一次绘制整张地图。
4. **⚠️ 最大的坑：macroquad 0.4.16 没有设置贴图环绕模式的公开 API，而默认是 `Clamp` 而不是 `Repeat`。** 如果你直接给出大于 1.0 的 UV 来做平铺，得到的是**边缘纹素被拉成条纹**，不是重复贴图。绕过的办法见第 14.2 节（用 `get_internal_gl()` + `texture_set_wrap`）。**这一步必须在加载贴图后立刻做，否则会浪费大量时间调试"为什么贴图是花的"。**

**验收**：地面能看出混凝土纹理、墙能看出金属板接缝、箱子能看出集装箱表面；近看和远看的贴图密度一致。

### A2　让四种人形有区别

**目标**：Grunt / Rusher / Heavy / Sniper 在 20 m 外能靠轮廓区分。

**方案一（低成本）**：给 `build_humanoid`（`src/enemy.rs:275`）加参数——肩宽、头型、腿长、背包/头盔/披风等配件，用 `KindStats` 里已有的字段驱动。不需要新的建模器，改的是同一个函数。

**方案二（中成本，收益更大）**：写一个最小 OBJ 解析器，把 `assets/models/characters/` 里那 6 个 Kenney 模型用上。文件已经完全三角化且带 `v`/`vt`/`vn`，配合现有的 `MeshBuilder` 大约 150 行。额外收益：这些模型带 `leg-left` / `leg-right` / `arm-left` / `arm-right` / `head` 分组，**可以直接解决第 4.2 节的行走动画问题**（当前只有巨像有）。

**验收**：把四种人形并排放在一起截图，不看颜色也能分辨。

### A3　给第一人称武器加手和手臂

**目标**：从"浮空的枪"变成"有人拿着"。

**实现要点**：在 `viewmodel.rs` 的视图空间里加两个前臂盒体 + 一个握把盒体，复用已有的盒体与投影管线（`project_point` / `Tri` 排序都已就绪，只需多提交几个实体）。建议同时给前臂一点随 `sway` 的滞后，成本极低但观感提升明显。

### A4　零成本的伪间接光

**目标**：消除"悬浮积木"的观感。

**实现要点**（都在 `mesh.rs` 与 `main.rs`）：

1. 在烘焙光照里按**世界高度**加一层暗化：越靠近地面的面越暗（相当于廉价的接触阴影），成本是一次乘加。
2. 加**线性雾**（`gl_use_material` 或直接按距离向雾色插值顶点色），让远处几何淡入天空色。R'LYEH 那种大场地受益最大。
3. 把受光面的 `f` 峰值从 1.116 压回 1.0 以下（现在是过曝后被钳掉，等于损失了亮部层次）。

**验收**：物体看起来"落"在地面上；远处几何不再突然撞进天空色。

## 14. 附录：第三方 API 事实（已核实，附绝对路径与行号）

### 14.1 网格只能挂一张贴图

`macroquad-0.4.16\src\models.rs:41-45`
```rust
pub struct Mesh {
    pub vertices: Vec<Vertex>,
    pub indices: Vec<u16>,
    pub texture: Option<Texture2D>,
}

pub fn draw_mesh(mesh: &Mesh) {
    let context = get_context();
    context.gl.texture(mesh.texture.as_ref());      // :50
```
**结论**：一个 `Mesh` 一个贴图槽。多材质场景必须拆成多个 `Mesh` / 多次 `draw_mesh`。

### 14.2 ⚠️ 贴图环绕模式默认是 Clamp，且 macroquad 没有公开的设值 API

`macroquad-0.4.16\src\texture.rs` 的 `Texture2D` 上只有 `set_filter`（`:837`），**没有 `set_wrap`**。
纹理创建走的是 miniquad，而默认参数是：

`miniquad-0.4.11\src\graphics.rs:405-418`
```rust
impl Default for TextureParams {
    fn default() -> Self {
        TextureParams {
            kind: TextureKind::Texture2D,
            format: TextureFormat::RGBA8,
            wrap: TextureWrap::Clamp,          // :410  <-- 注意：不是 Repeat
            min_filter: FilterMode::Linear,
            mag_filter: FilterMode::Linear,
            mipmap_filter: MipmapFilterMode::None,
            // ...
        }
    }
}
```
枚举值：`TextureWrap::Repeat`（`graphics.rs:348`）、`TextureWrap::Mirror`、`TextureWrap::Clamp`（`:352`）。

**绕过办法**：miniquad 的渲染后端暴露了
```rust
fn texture_set_wrap(&mut self, texture: TextureId, wrap_x: TextureWrap, wrap_y: TextureWrap);
    // miniquad-0.4.11\src\graphics.rs:1197
```
而 macroquad 提供了拿到它的入口：

`macroquad-0.4.16\src\window.rs:36-54`
```rust
pub struct InternalGlContext<'a> {
    pub quad_context: &'a mut dyn miniquad::RenderingBackend,
    pub quad_gl: &'a mut crate::quad_gl::QuadGl,
}

pub unsafe fn get_internal_gl<'a>() -> InternalGlContext<'a> { /* ... */ }
```
加上 `Texture2D::raw_miniquad_id(&self) -> miniquad::TextureId`（`macroquad-0.4.16\src\texture.rs:848`），完整做法是：

```rust
use macroquad::miniquad::TextureWrap;   // macroquad 重新导出了 miniquad，见 window.rs:7 的注释

let tex = load_texture("assets/textures/concrete_floor.png").await?;
tex.set_filter(FilterMode::Linear);
// 安全：只设置采样器参数，不触碰 macroquad 的批处理状态。
// 必须在任何 draw_mesh 之前调用。
unsafe {
    let mut gl = macroquad::window::get_internal_gl();
    gl.quad_context.texture_set_wrap(
        tex.raw_miniquad_id(),
        TextureWrap::Repeat,
        TextureWrap::Repeat,
    );
}
```

**注意**：`get_internal_gl()` 是 `unsafe fn`，调用点应写 `// SAFETY:` 注释说明"只修改采样器环绕参数，不影响批处理状态"。

### 14.3 贴图格式限制

macroquad 0.4.16 的 `image` 依赖启用了 `png` 和 `tga`（`assets/MANIFEST.md:162-164` 已记录）。当前 6 张贴图都是 PNG，**可以直接加载**。

### 14.4 模型加载

macroquad 0.4.16 **没有任何模型加载器**（`macroquad-0.4.16\src\models.rs` 只有 `draw_cube` / `draw_sphere` 等程序化辅助函数和 `Mesh` 结构，没有 `load_model`，也没有任何 feature flag 能打开它）。要用 `assets/models/` 下的 OBJ，必须自己写解析器或引入 `tobj` 之类的依赖。

## 15. 附录：`target/hudshots/` 的截图是什么

`target/` 已被 `.gitignore` 排除，所以这个脚手架不会进仓库——但若它仍在本地，**它的存在会让人误以为这些截图代表游戏的真实观感**，建议在完成美术改造后重新生成一批截图。
