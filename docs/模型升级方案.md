# 模型升级方案：从 Poly Haven 引入精致角色模型

> 撰写日期：2026-10-09
> 适用项目：`D:\Documents\tides-of-rlyeh`（TIDES OF R'LYEH / 拉莱耶的潮声）
> 当前版本：Rust 1.85+ + macroquad 0.4.16

---

## 问题陈述

当前游戏使用的角色模型来自 Kenney **Blocky Characters 2.0**，每个角色只有 **72 个三角片**（44 vertices × 143 UVs × 19 normals），单色纹理贴图，且 macroquad 没有模型加载器——所有模型都需要在 Rust 里手工 author。玩家看到的是一排 Minecraft 风格的方块人：正面看还行，一转个角就只剩几个平面。

这不是代码问题，是**源资产的问题**。MANIFEST.md 明确写了：`texture-b.png` 是单色，vertex color 试图补偿但被 baked lighting 锁死在 1.0 以内。

---

## 方案概述

用外部高质量模型替换 Kenney 方块人，通过 `obj-rs` crate 解析 Wavefront OBJ 格式，利用现有的 `MeshBuilder` 基础设施烘焙 UV 和顶点颜色，零分配重绘范式直接复用。

```
当前流程：
  Rust 手工 author 72-tri mesh → MeshBuilder 套单色纹理

改进流程：
  Poly Haven / 外部源下载 FBX/OBJ → obj-rs 解析 
  → MeshBuilder 烘焙 UV/顶点颜色 
  → 零分配每帧重绘（与敌人动画一致）
```

### 推荐渠道

| 平台 | 适用场景 | 成本 |
|------|----------|------|
| **Poly Haven** (premium 会员) | CC0 + 付费高质量模型，含完整贴图 | ~$15/月 |
| **Unity Asset Store / Catalog** | 游戏优化模型，直接导出 FBX | $5–$50/个 |
| **Unreal Marketplace** | 高面数精致角色，带动画 | $10–$100/个 |
| **Mixamo (Adobe)** | 免费可绑定模型，适合替换动画 | 免费 |

### Poly Haven API 搜索

```bash
# 用 API 搜 CC0 角色模型
https://api.polyhaven.com/assets?search=scifi+character&license=CC0
```

**关键筛选条件**：
- 格式：**FBX 或 OBJ**（不要 GLTF，Rust 读 FBX 更稳）

- CC0 或可商用授权

### 备选：Mixamo + Blender

如果找不到合适的 CC0 角色，去 Mixamo 找免费模型，然后在 Blender 里导入后做简单调整，再导出为 OBJ。Poly Haven 的 `export` 功能也可以直接出 OBJ+ 贴图。

## 第二步：添加 obj-rs 依赖

```bash
cargo add obj
```

`obj-rs`（v0.7）是一个成熟的 Wavefront OBJ 解析器，输出结构：

```rust
pub struct Obj {
    pub name: String,
    pub materials: Vec<Material>,
    pub groups: Vec<Group>,
    pub meshes: Vec<Mesh>,
}

pub struct Mesh {
    pub name: String,
    pub vertices: Vec<Vertex>,   // Vertex { x, y, z, tc, n }
    pub normals: Vec<Normal>,
    pub tangents: Vec<Tangent>,
    pub indices: Indices,         // 内部索引格式需转为 u16 slice
    pub material_index: usize,
}
```

**注意**：`obj-rs` 的 `Indices` 是 `Vec<u32>`，需要手动转为 `Vec<u16>`（max 65536 顶点，游戏 mesh 都在这个范围内）。

## 第三步：编写 OBJ 解析器

新建文件 `src/models.rs`：

```rust
//! OBJ model loader using obj-rs.
//!
//! Models are baked into Mesh form to integrate with MeshBuilder's
//! zero-allocation rebuild paradigm. Each character is loaded once at
//! startup and cached, then transformed per-frame for animation.

use obj::{Mesh as ObjMesh, Vertex, Group};
use std::path::Path;
use std::fs::File;
use std::io::Read;

/// A simplified vertex that matches MeshBuilder's expectations.
/// macroquad's Vertex { position, uv, color, normal } — normal is free
/// channel (never read by the shader), so we keep it for full flexibility.
#[derive(Clone, Debug)]
pub struct GameVertex {
    pub pos: (f32, f32, f32),
    pub uv: (f32, f32),
    pub color: [u8; 4],
    pub normal: (f32, f32, f32),
}

/// Loaded model ready to be passed to MeshBuilder.
#[derive(Clone)]
pub struct LoadedModel {
    /// Pre-computed vertices and indices for direct use with MeshBuilder.
    pub vertices: Vec<GameVertex>,
    pub indices: Vec<u16>,
    /// Path to the texture folder relative to model file.
    pub texture_path: String,
}

/// Load a Wavefront OBJ into Game-form mesh.
///
/// # Panics
/// Panics on IO errors or malformed OBJ (used in tests, not production).
pub fn load_model(path: &Path) -> Result<LoadedModel, Box<dyn std::error::Error>> {
    let obj = File::open(path)?.read_to_string(&mut String::new())?;
    let parsed: ObjMesh = serde_json::from_str(&obj)?;

    let mut vertices = Vec::new();
    let mut indices = Vec::new();

    for mesh in parsed.meshes {
        // Merge vertices by index (obj-rs may duplicate them)
        let mut vertex_map = std::collections::BTreeMap::new();
        for (i, v) in mesh.vertices.drain(..).enumerate() {
            *vertex_map.entry(i as u64).or_insert(v) = v;
        }

        // Build indices, resolving vertices and UVs
        for tri in mesh.indices.triangles.iter() {
            let a = vertex_map.get(&tri[0]).unwrap();
            let b = vertex_map.get(&tri[1]).unwrap();
            let c = vertex_map.get(&tri[2]).unwrap();

            // Apply texture coordinates and normals
            let va = GameVertex {
                pos: (a.x, a.y, a.z),
                uv: (a.tc.0, a.tc.1),
                color: [255, 255, 255, 255], // will be tinted by MeshBuilder
                normal: (a.n.0, a.n.1, a.n.2),
            };
            let vb = GameVertex {
                pos: (b.x, b.y, b.z),
                uv: (b.tc.0, b.tc.1),
                color: [255, 255, 255, 255],
                normal: (b.n.0, b.n.1, b.n.2),
            };
            let vc = GameVertex {
                pos: (c.x, c.y, c.z),
                uv: (c.tc.0, c.tc.1),
                color: [255, 255, 255, 255],
                normal: (c.n.0, c.n.1, c.n.2),
            };

            // Store in a temporary vec for MeshBuilder to consume
            vertices.push(va);
            vertices.push(vb);
            vertices.push(vc);
        }
    }

    let texture_path = parsed
        .materials
        .first()
        .and_then(|m| m.texture_file.as_ref())
        .ok_or("model has no material/texture reference")?
        .clone();

    Ok(LoadedModel {
        vertices,
        // Convert u32 indices to u16 (game mesh cap is 65536)
        indices: parsed
            .indices
            .triangles
            .iter()
            .flat_map(|t| t.iter().map(|&i| i as u16))
            .collect(),
        texture_path,
    })
}
```

**关键简化**：上面的示例用 `serde_json` 解析 OBJ，但 `obj-rs` 原生输出是 struct 而非 JSON。实际代码需要直接用 `obj::Obj` 的 struct 字段，避免序列化开销。核心逻辑是：

1. **解析 v / vt / vn** → 顶点位置、UV 坐标、法线
2. **合并同名顶点** → 去掉 duplicate vertices
3. **构建三角面索引** → 按顺序喂给 `MeshBuilder`

## 第四步：整合到 MeshBuilder

利用现有的零分配重绘范式，把加载后的 mesh 直接交给 `MeshBuilder`：

```rust
// In src/mesh.rs, reuse the existing pattern:

impl LoadedModel {
    /// Reclaim a fresh builder from an existing mesh.
    pub fn reclaim(mesh: &mut Mesh) -> MeshBuilder {
        MeshBuilder::reclaim(mesh)
    }
}

// In enemy.rs or a new models.rs:
fn build_character_mesh(model: &LoadedModel, tint: Color) -> Mesh {
    let mut builder = MeshBuilder::reclaim(&mut Mesh::default());
    
    for vertex in &model.vertices {
        builder.set_position(vertex.pos.0);
        builder.set_uv(vertex.uv.0);
        builder.set_color(tint); // or tint blended with vertex color
        builder.set_normal(vertex.normal.0);
    }
    
    builder.set_indices(&model.indices);
    builder.finish()
}
```

**关键要点**：
- 不需要修改 `MeshBuilder` 本身——它已经支持每帧重建 mesh（敌人动画用的就是这套范式）
- 只需要把加载后的顶点数据喂进去，UV 通过世界位置烘焙
- 顶点颜色可以统一设为角色专属色，由 texture 提供细节

## 技术挑战与解决方案

### 挑战 1：obj-rs 的索引类型是 u32

**问题**：`MeshBuilder` 用 `Vec<u16>`，`obj-rs` 输出 `Vec<u32>`。

**方案**：游戏 mesh 最大顶点数远小于 65536（一个角色即使 10k tri = 30k vertices），直接转 `u16`。

### 挑战 2：macroquad 没有模型加载器

**问题**：必须手动构建 Mesh，不能依赖 `load_model`。

**方案**：用 `obj-rs` 解析 OBJ → 喂给 `MeshBuilder`。这是唯一需要外部 crate 的地方。

### 挑战 3：骨骼动画（Skinned Mesh）

**问题**：macroquad 0.4.16 没有 skeletal animation 支持，无法做 bone binding + skinning shader。

**方案**：**短期不做**。用静态 mesh + 硬编码 transform（像现有 enemy.rs 的 limb swing 那样，在 `build_character_mesh` 里每帧乘一个简单的旋转矩阵）。如果要真做 ES 1.0 skinning shader，需要从零写 material 代码，是下一阶段的事。

### 挑战 4：面数过高导致游戏卡顿

**问题**：Poly Haven 的 premium 模型可能达到 5k–20k tri。

**方案**：**LOD（Level of Detail）**——静态 mesh，按距离相机远近切换低多边形版本。或者直接在下载时要求作者降低面数到 2k–5k 以内。

## 实施路线图

### Phase 1：单个角色试点（1–2 周）

1. 从 Poly Haven / Mixamo 下载一个 CC0 或付费角色模型（FBX/OBJ，带贴图）
2. 加 `obj-rs` 依赖，写解析器
3. 用 `MeshBuilder` 烘焙 UV，放到 `assets/characters/Textures/`
4. 验证：在测试里跑一个角色 mesh，确认渲染正确

**验收标准**：
- [ ] 模型能正确加载并渲染
- [ ] UV mapping 正确（纹理不拉伸）
- [ ] 顶点数 < 5000
- [ ] 测试 suite 通过（包括 `every_level_face_samples_one_uv_field`）

### Phase 2：全部角色替换（1–2 周）

1. 为 6 个角色各下载一个匹配风格的模型
2. 重复 Phase 1，批量处理
3. 更新 `Asset::Sfx*` 枚举中的角色 mesh 引用（如果需要）

**验收标准**：
- [ ] 6 个角色全部替换完成
- [ ] 每个角色的 polycount 在 2k–5k 范围内
- [ ] 纹理与模型匹配（没有 UV 错位）

### Phase 3：动画系统（可选，2–4 周）

1. 从 FBX 提取 bone matrix（64 bones per character）
2. 写 GLSL ES 1.0 custom material with skinning
3. 每帧更新 bone uniforms，mesh 动态 transform

**验收标准**：
- [ ] 敌人 limb animation 升级为真实骨骼动画
- [ ] 走/站/死姿态切换工作
- [ ] 性能：每帧 < 500 allocations（目前已是 0）
